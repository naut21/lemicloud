cómo subir y consumir la API
01

Subir archivo (multipart)

Una sola llamada HTTP. Internamente se divide en chunks de 3MB y se distribuye en los 4 repos de GitHub. Sin límite de tamaño.

POST /api/upload
Content-Type: multipart/form-data

curl -F "file=@foto.png" https://lemicloud.app/api/upload
02

Subir archivo (raw body)

Envía el archivo directamente como cuerpo. Pasa ?name= para sugerir nombre/extensión; si no, se detecta por magic bytes.

POST /api/upload?name=cat.jpg
Content-Type: application/octet-stream

curl -X POST "https://lemicloud.app/api/upload?name=cat.jpg" \
  --data-binary @cat.jpg
03

Subir por URL remota

LemiCloud descarga el archivo y lo procesa como upload normal. útil cuando no quieres descargarlo tú primero.

POST /api/upload-url
Content-Type: application/json

{ "url": "https://ejemplo.com/imagen.png" }

curl -X POST https://lemicloud.app/api/upload-url \
  -H "Content-Type: application/json" \
  -d '{"url":"https://ejemplo.com/imagen.png"}'
04

Respuesta de la API

Todas las subidas devuelven el mismo JSON. La URL proxy ya incluye la extensión real del archivo.

{
  "id": "5f4a3b2c",
  "name": "5f4a3b2c.png",
  "original_name": "foto.png",
  "extension": "png",
  "mime_type": "image/png",
  "size": 2048576,
  "width": 1920,
  "height": 1080,
  "chunks": 1,
  "created_at": 1783877943874,
  "url": "/p/5f4a3b2c",
  "raw": "/p/5f4a3b2c/5f4a3b2c.png"
}
05

Acceder al archivo (proxy)

URL corta redirige (302) a la URL con extensión. Reensambla los chunks desde GitHub y los transmite con el MIME correcto.

GET /p/<id>        → 302 → /p/<id>/<name>.<ext>
GET /p/<id>/<name>.<ext>  → archivo binario

https://lemicloud.app/p/5f4a3b2c
https://lemicloud.app/p/5f4a3b2c/5f4a3b2c.png
06

Listar archivos

Devuelve todos los archivos ordenados por fecha descendente.

GET /api/files

curl https://lemicloud.app/api/files
07

Eliminar archivo

Borra los chunks de GitHub y la fila de la base de datos. Irreversible.

DELETE /api/file/<id>

curl -X DELETE https://lemicloud.app/api/file/5f4a3b2c
